Reselling SMM services via an API

How to build SMM service resale on top of an OpenSMM node: the order arrives over REST /v0 or MCP /mcp, a panel fulfils it, and repeating one request never creates a second order.

1. Two payment topologies

The protocol is not tied to a settlement method: the payee address PaymentRequirement.payTo decides who receives the money, and both variants are valid OpenSMM.

  • Direct settlement (canonical). payTo is the provider's address. The agent pays the provider directly (x402, USDC on Base); the gateway holds no funds and takes no part in the transaction. The gateway earns no margin in this mode.
  • Gateway-as-merchant (optional mode). payTo is the gateway's address. It is needed when the supply source only debits a prepaid balance (classic panel APIs) and the gateway operator becomes the seller to its own users. Margin, refunds and buyer protection live in this mode, and so does the regulatory burden of custody.

The operator chooses the mode; it is not enabled by default. The gateway never mixes topologies within one payment intent: the payer sees the payee before paying. Source: spec/v0.

2. One order for any retry

For resale it matters not to charge a customer twice. Idempotency is built into the protocol: Idempotency-Key in REST and clientReference in MCP; a repeat returns the same order.

flow
search_services → get_quote → create_order (clientReference)
repeat with the same clientReference → the same orderId

A quote is required before an order and is spent once. Payment and execution statuses are two separate state machines: paymentStatus and executionStatus. More: OpenSMM or a direct panel API.

3. Connect a provider

The supply source is an SMM panel: the node needs a baseUrl, an apiKey and a profile, no code. How it works: Connect an SMM panel to AI agents; the profile is described here; transports and tools: MCP for SMM panels.

Honest limitations

  1. The protocol does not set margin or prices and this page gives none: that is the gateway operator's decision.
  2. x402 payments are tested with USDC on Base Sepolia — testnet.
  3. The public catalog is a demo (mock fixtures with synthetic: true) until the first panel is connected.
  4. The npm package is not published: the node runs from a repository checkout.
