Перепродажа SMM-услуг через API

Как построить перепродажу SMM-услуг поверх узла OpenSMM: заказ приходит по REST /v0 или MCP /mcp, исполняет панель, а повтор одного запроса не создаёт второй заказ.

1. Две топологии оплаты

Протокол не привязан к способу расчётов: адрес получателя платежа PaymentRequirement.payTo определяет, кто принимает деньги, и оба варианта считаются OpenSMM.

  • Прямой расчёт (канонический). payTo — адрес исполнителя. Агент платит ему напрямую (x402, USDC в сети Base), гейтвей не держит средства и не участвует в транзакции. Маржи у гейтвея в этом режиме нет.
  • Gateway-as-merchant (необязательный режим). payTo — адрес гейтвея. Нужен, когда источник списывает только предоплаченный баланс (классические API панелей) и оператор гейтвея сам становится продавцом для своих пользователей. Маржа, возвраты и защита покупателя живут в этом режиме, как и регуляторная нагрузка кастоди.

Режим выбирает оператор самостоятельно, он не включён по умолчанию. Гейтвей не смешивает топологии в одном платёжном намерении: плательщик видит получателя до оплаты. Источник — spec/v0.

2. Один заказ на любой повтор

Для перепродажи важно не списать клиента дважды. Идемпотентность заложена в протокол: Idempotency-Key в REST и clientReference в MCP, повтор возвращает тот же заказ.

flow
search_services → get_quote → create_order (clientReference)
повтор с тем же clientReference → тот же orderId

Котировка обязательна перед заказом и расходуется один раз. Статусы оплаты и исполнения — два отдельных автомата: paymentStatus и executionStatus. Подробнее: OpenSMM или прямой API панели.

3. Подключить исполнителя

Источник предложения — SMM-панель: узлу нужны baseUrl, apiKey и профиль, без кода. Как это делается — на странице «Подключить SMM-панель к AI-агентам», профиль — здесь, транспорты и инструменты — MCP для SMM-панелей.

Честные ограничения

  1. Размер маржи и цены не задаются протоколом и на этой странице не приводятся: это решение оператора гейтвея.
  2. Платежи x402 проверяются на USDC Base Sepolia — testnet.
  3. Публичный каталог — демонстрация (mock-фикстуры с synthetic: true), пока первая панель не подключена.
  4. Пакет npm не опубликован: узел запускается из чекаута репозитория.
