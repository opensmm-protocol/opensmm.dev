SMM API для MCP

OpenSMM — открытый протокол заказа SMM-услуг, и MCP — один из его транспортов. MCP-клиент подключается к /mcp узла гейтвея (Streamable HTTP, заголовок accept: application/json, text/event-stream) и получает каталог, котировки и исполнение заказов десятью инструментами. Рядом работает канонический REST-биндинг /v0 — те же объекты, те же правила.

Десять инструментов, один контракт

get_capabilities

Версия протокола, команды, способы оплаты, версия каталога.

search_services

Поиск услуг по тексту, платформе и цели.

get_service

Цена и база тарифа, min/max, параметры, поддержка дозаказа и отмены.

get_quote

Котировка с ценой и сроком. Обязательна перед заказом.

create_order

Идемпотентное создание заказа; отвечает требованиями к оплате.

get_order_status

Статусы оплаты и исполнения; безопасный опрос.

cancel_order

Отмена там, где услуга её поддерживает.

request_refill

Дозаказ при откатах на завершённых или частичных заказах.

list_providers

Псевдонимные узлы с метриками, измеренными гейтвеем.

register_provider

Подключение поставщика — без заявок, email и форм.

MCP и REST — одни и те же объекты

REST /v0 — канонический HTTP-биндинг протокола, MCP — равноправный транспорт. Та же операция через REST и MCP возвращает одни и те же доменные объекты. Идемпотентность — на уровне протокола: REST передаёт заголовок Idempotency-Key, MCP — поле clientReference; повтор запроса возвращает тот же заказ. Один clientReference → один orderId на любом транспорте — агент может смешивать MCP и REST, не создавая дублей.

Суммы — десятичные строки в целых микро-единицах, никогда float. Коды ошибок канонические и одинаковые на обоих транспортах: от VALIDATION_FAILED до IDEMPOTENCY_CONFLICT и INTERNAL.

Как подключить агента

Укажите MCP-клиенту адрес узла гейтвея и вызывайте инструменты в порядке сценария: get_capabilities → search_services → get_quote → create_order → оплата по требованиям из ответа 402 → get_order_status до COMPLETED. Котировка обязательна перед заказом и расходуется ровно один раз; заказ отвечает HTTP 402 с требованиями к оплате — USDC на Base Sepolia (testnet), напрямую провайдеру, мимо гейтвея.

Спека протокола, JSON-схемы и примеры вызовов — в каталоге spec/v0 репозитория; манифест MCP-сервера — mcp.json.

Откуда берутся услуги

Услуги в узел приносит поставщик: SMM-панель подключается одной регистрацией — baseUrl, apiKey и профиль поведения, без кода (адаптер smm-v2). Пока поставщика нет, узел отдаёт mock-каталог: каждая услуга помечена "synthetic": true — fixtures для отладки агента end-to-end, а не продаваемое предложение. Публичный каталог сайта — демонстрационный снапшот такого mock-узла.

Выбор поставщика — через list_providers: узлы псевдонимны, а показатели качества гейтвей измеряет по своим реальным заказам — самоотчёты запрещены. Новый узел стартует со статусом UNVERIFIED и объёмным ограничением на заказ, в ACTIVE его переводят измеренные заказы; открытая формула качества — в спеке, §9.1: показатели можно пересчитать самому.

Последний шаг: поднять свой узел

Свой узел гейтвея — это один процесс с REST /v0 и MCP /mcp на одном порту, без ключей и внешних сервисов. Нужен Node.js ≥ 22.18 — и ничего больше.
