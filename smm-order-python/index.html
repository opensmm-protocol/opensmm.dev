Заказ SMM-услуги из Python-агента

Готовый REST-клиент против локального узла OpenSMM на чистом Python: только urllib.request и json из стандартной библиотеки — без pip install, без SDK, без ключей и денег. Сценарий целиком: capabilities → каталог → котировка → заказ → повтор по clientReference.

1. Поднять узел (около 2 минут)

Узлу нужен Node.js ≥ 22.18; Python-клиенту хватает Python 3 со стандартной библиотекой.

bash
git clone https://github.com/opensmm-protocol/mcp-server.git
cd mcp-server
npm ci
npm run gateway

Узел печатает на stderr строку вида gateway listening on http://localhost:8080 (REST /v0, MCP /mcp; provider: mock, mock catalog — not real supply). Порт занят? PORT=8081 npm run gateway. Другие сбои запуска — сбои запуска узла.

2. Запустить REST-клиент (второй терминал)

bash
python3 examples/rest-client.py http://127.0.0.1:8080 --client-reference my-first-order
text
node:    http://127.0.0.1:8080
protocol: 0.1.0 - 10 commands, payment: mock
catalog: MOCK - every service is marked synthetic: not real supply, no real money
service: osmm_svc_tg_members_std - Telegram Channel Members — Standard
quote:   osmm_quote_... - 0.241200 USDC for 100 (mock rate)
order:   osmm_order_... - REQUIRES_PAYMENT, clientReference "my-first-order"
replay:  osmm_order_... - same orderId, no second order created
done:    Python client OK

Опции: [base-url] (по умолчанию http://127.0.0.1:8080), --client-reference <ref> (по умолчанию python-demo-<timestamp>), --quote <quote-id> — переиспользовать котировку из прошлого запуска, --help.

3. Какие HTTP-запросы делает клиент

  1. GET /v0/capabilities — версия протокола, список команд и платёжных методов узла.
  2. GET /v0/services — каталог; клиент берёт первую услугу из ответа узла и останавливается, если она не помечена synthetic: true.
  3. POST /v0/quotes — котировка для количества 100 и ссылки. Котировка расходуется один раз, под каждый заказ нужна своя.
  4. POST /v0/orders — заказ. Узел отвечает HTTP 402 с телом заказа — это ожидаемо, а не сбой: заказ остаётся в статусе REQUIRES_PAYMENT, ничего не оплачивается и не исполняется.
  5. POST /v0/orders ещё раз с тем же clientReference — повтор возвращает сохранённый заказ, а не создаёт второй.

MCP-эквиваленты тех же операций: POST /mcp, инструменты search_services, get_quote, create_order — MCP-клиент на Node.js.

4. Защита от живого провайдера

  • Клиент берёт первую услугу из ответа узла — не придумывает ID — и сразу останавливается, если она не помечена synthetic: true.
  • Сообщение об ошибке: refusing to place a demo order: ... is not marked synthetic. This example orders only on the mock catalog — see examples/README.md.
  • Это защита от узла, к которому подключён живой провайдер: демо-заказ не уйдёт в реальное предложение.

5. Если что-то выглядит неправильно

  • is not marked synthetic — узел не на mock-каталоге; остановитесь и не заказывайте. Перезапустите узел без настроенного провайдера.
  • error: ... с подсказкой start a node first — npm run gateway — узел из шага 1 не запущен или слушает другой порт.
  • IDEMPOTENCY_CONFLICT — этот clientReference уже принадлежит заказу из другой котировки: передайте исходную через --quote или возьмите новый референс.
  • HTTP 402 на POST /v0/orders — ожидаемый ответ: клиент читает тело заказа прямо из него.

Честные ограничения

  1. Страница пересказывает examples/README.md в репозитории mcp-server; точный вывод и опции скрипта — там.
  2. Каталог — mock (synthetic: true): реальных услуг, цен и заказов здесь нет; курс в примере — тестовый, оплата не проходит.
  3. Другие стеки: быстрый старт агента, MCP-клиент на Node.js, агент в стиле LangChain.
