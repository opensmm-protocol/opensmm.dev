Развёртывание узла OpenSMM

Запуск узла из исходников и через Docker Compose, проверка и выход в публичную сеть за прокси.

1. Из исходников

Узел — один процесс: REST /v0 и MCP /mcp на одном порту (по умолчанию 8080). Нужен Node.js ≥ 22.18. Ключей и внешних сервисов не нужно: узел стартует на встроенном mock-каталоге.

bash
git clone https://github.com/opensmm-protocol/mcp-server.git
cd mcp-server
npm ci
PORT=8080 OPENSMM_STATE_FILE=./opensmm-state.json npm run gateway

Состояние (заказы, метрики, самостоятельно зарегистрированные узлы) лежит в одном JSON-снимке; с OPENSMM_STATE_FILE на томе узел переживает рестарт. Без переменной состояние только в памяти.

2. Docker Compose

Образ собирается локально из чекаута: публичного образа и пакета npm нет. Compose монтирует том opensmm-data под состояние и привязывает порт к loopback.

bash
docker compose up --build -d
docker compose ps   # в столбце STATUS — healthy

Healthcheck опрашивает GET /v0/services внутри контейнера, поэтому healthy значит «готов принять заказ». Без Compose: docker build -t opensmm-gateway . и docker run -d --name opensmm -p 127.0.0.1:8080:8080 -v opensmm-data:/data opensmm-gateway.

3. Проверка узла

Проверка живости процесса — /health; полная проверка (каталог и MCP initialize) — те же две пробы, что использует перепись.

bash
curl -s http://127.0.0.1:8080/health
npm run verify:node -- http://127.0.0.1:8080

Код выхода 0 — перепись засчитает узел. Определение узла и перепись — docs/NODES.md.

4. Публичный адрес: TLS и безопасность

У узла нет TLS и собственной авторизации, поэтому наружу его выставляют только за прокси.

  • порт открыт только на loopback, снаружи — 80/443 через обратный прокси (например Caddy: reverse_proxy 127.0.0.1:8080);
  • OPENSMM_TRUST_PROXY=1 — только если прокси перезаписывает x-forwarded-for;
  • состояние хранится на постоянном томе; файл состояния содержит учётные данные провайдера, права 0600, храните как секрет;
  • OPENSMM_ALLOW_PRIVATE_ENDPOINTS не задавайте — это dev-обход защиты от SSRF.

Без постоянного домена для проверки подойдёт бесплатный туннель Cloudflare (cloudflared tunnel --url http://127.0.0.1:8080), но его адрес временный. Полный разбор — docs/DEPLOY.md.

Честные ограничения

  1. Пакет npm и публичный образ не опубликованы: узел собирается из чекаута репозитория.
  2. Локальный узел отдаёт mock-каталог (synthetic: true), а не реальное предложение.
  3. Живой провайдер подключается через OPENSMM_REST_V1_*, это отдельный шаг.
