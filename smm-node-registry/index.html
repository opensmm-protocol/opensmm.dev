Реестр узлов OpenSMM

Как протокол считает внешние узлы: определение узла, проверка своего узла, заявка в недельную перепись — и честный статус OpenSMM в официальном MCP Registry.

Что считается узлом протокола

Публичный URL считается узлом, когда проходят обе проверки (редиректы не следуются):

  • GET <url>/v0/services — 200 с JSON-массивом services;
  • POST <url>/mcp с initialize (JSON-RPC) — 200 с JSON-RPC result.

GET <url>/v0/providers — информационный: он никогда не решает вердикт. Определение узла и перепись — docs/NODES.md.

Проверить свой узел перед заявкой

Перед недельной переписью прогоните те же две проверки локально. Скрипт печатает PASS/FAIL по каждой проверке и вердикт: код выхода 0 — перепись засчитает узел, 1 — нет.

bash
npm run verify:node -- http://127.0.0.1:8080
вывод
PASS  GET /v0/services — 6 services in the catalog
PASS  POST /mcp initialize — 2025-06-18, server opensmm
PASS  GET /v0/providers — 1 provider registered   (informational, not counted)

PASS — the census counts this node: 2/2 required checks passed in 1315 ms

Скрипт импортирует те же пробы, что и перепись: одна формулировка узла, поэтому локальный PASS значит, что перепись увидит тот же узел. Для узла за прокси или на публичном хосте передавайте URL, по которому перепись будет обращаться (редиректы не следуются — используйте финальный URL).

Для мониторинга есть машиночитаемый вывод: --json печатает тот же результат JSON на stdout — для cron-задачи или шага CI, который алертит на упавший узел.

bash
npm --silent run verify:node -- --json http://127.0.0.1:8080 | jq .entry.status
node scripts/verify-node.mjs --json http://127.0.0.1:8080 | jq .entry.status

В JSON entry.status — "up" или "down", checks — отчёт по каждой проверке, где required: false отмечена проверка, которая никогда не решает вердикт. Ежедневный cron-чек с алертом через код выхода:

bash
npm --silent run verify:node -- --json https://mcp.example.org > /var/log/opensmm-verify.json \
  || echo "OpenSMM node is down" >&2

--timeout <ms> — один бюджет на все три пробы узла: по умолчанию 5000 мс, допустимый диапазон 1000–30000 мс. На медленной сети поднимите его, чтобы доступный узел не был отмечен как недоступный.

Заявка в недельную перепись

Когда узел проходит проверку локально и доступен публично, подайте его URL в недельную перепись через issue-шаблон: issues/new?template=node-report.md.

Сама перепись запускается одной командой по списку URL:

bash
npm run census -- --url http://127.0.0.1:8080 --url https://mcp.opensmm.dev
npm run census -- --file nodes.txt   # один URL в строке, "#" начинает комментарий

Лимит — 20 URL за запуск. JSON печатается на stdout, сводка — на stderr. Недоступный узел — данные, а не сбой: status: "down", код выхода 0. Код выхода 1 — сломанные аргументы. Итог недели — одна строка вида 2026-11-09 — 1 node up of 3 checked: … с JSON под ней.

Публичный URL без своего домена

Перепись засчитывает только публично доступные URL по HTTPS/HTTP. Если своего домена и TLS-прокси пока нет, локальный шлюз можно выставить наружу бесплатным quick-туннелем Cloudflare без создания аккаунта.

bash
npm run gateway                                          # узел на 8080
cloudflared tunnel --url http://127.0.0.1:8080           # во втором терминале
npm run verify:node -- https://…trycloudflare.com        # проверка публичного адреса

Туннель печатает временный адрес *.trycloudflare.com: он меняется при каждом перезапуске процесса туннеля. Для постоянного узла настройте TLS на своём домене с Caddy — docs/DEPLOY.md.

Статус в официальном MCP Registry

OpenSMM не записан в официальный MCP Registry, и это ожидаемый результат: GET https://registry.modelcontextprotocol.io/v0/servers?search=opensmm отвечает {"servers":[],"metadata":{"count":0}}.

Схема 2025-12-11 принимает сервер только с опубликованным пакетом (packages[] с registryType и identifier) или с remotes на публичный hosted-endpoint. У OpenSMM нет ни того, ни другого: пакет не опубликован, образ контейнера приватный, публичного hosted MCP endpoint нет. Изобретать packages или remotes нельзя.

Ситуацию изменит опубликованный пакет или публичный hosted MCP endpoint. До тех пор узел ставится из исходников — «Run a node from source in 5 minutes» в README.

Честные ограничения

  1. Пока записи в MCP Registry нет: без опубликованного пакета или публичного hosted-endpoint реестр не принимает сервер, а выдумывать packages или remotes нельзя.
  2. Локальный узел отдаёт mock-каталог (synthetic: true), а не реальное предложение.
  3. Перепись засчитывает только публично доступные URL: localhost-узел проверяют локально, но в перепись он не попадает.
