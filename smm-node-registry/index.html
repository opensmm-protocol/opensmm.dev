OpenSMM node registry

How the protocol counts external nodes: the definition of a node, checking your own node, reporting it to the weekly census — and the honest status of OpenSMM in the official MCP Registry.

What counts as a protocol node

A public URL is a node when both checks pass (redirects are not followed):

  • GET <url>/v0/services — 200 with a JSON services array;
  • POST <url>/mcp with initialize (JSON-RPC) — 200 with a JSON-RPC result.

GET <url>/v0/providers is informational: it never decides the verdict. The node definition and the census live in docs/NODES.md.

Check your own node before reporting

Before the weekly census, run the same two checks locally. The script prints PASS/FAIL per check and a verdict: exit code 0 — the census counts the node, 1 — it does not.

bash
npm run verify:node -- http://127.0.0.1:8080
output
PASS  GET /v0/services — 6 services in the catalog
PASS  POST /mcp initialize — 2025-06-18, server opensmm
PASS  GET /v0/providers — 1 provider registered   (informational, not counted)

PASS — the census counts this node: 2/2 required checks passed in 1315 ms

The script imports the same probes as the census: one definition of a node, so a local PASS means the census sees the same node. For a node behind a proxy or on a public host, pass the URL the census will call (redirects are not followed — use the final URL).

Machine-readable output for monitoring: --json prints the same result as JSON on stdout — for a cron job or a CI step that alerts on a down node.

bash
npm --silent run verify:node -- --json http://127.0.0.1:8080 | jq .entry.status
node scripts/verify-node.mjs --json http://127.0.0.1:8080 | jq .entry.status

In the JSON, entry.status is "up" or "down", and checks is the per-check report where required: false marks a check that never decides the verdict. A daily cron check that alerts through its exit code:

bash
npm --silent run verify:node -- --json https://mcp.example.org > /var/log/opensmm-verify.json \
  || echo "OpenSMM node is down" >&2

--timeout <ms> is one budget for all three probes of a node: default 5000 ms, allowed range 1000–30000 ms. On a slow network raise it, so a reachable node is not reported as down.

Report your node to the weekly census

Once your node passes locally and is publicly accessible, submit its URL for the weekly census via the issue template: issues/new?template=node-report.md.

The census itself runs over a list of URLs with one command:

bash
npm run census -- --url http://127.0.0.1:8080 --url https://mcp.opensmm.dev
npm run census -- --file nodes.txt   # one URL per line, "#" starts a comment

The limit is 20 URLs per run. JSON goes to stdout, the summary to stderr. An unreachable node is data, not a failure: status: "down", exit 0. Exit 1 means broken arguments. The weekly result is one line like 2026-11-09 — 1 node up of 3 checked: … with the JSON below it.

A public URL without a custom domain

The census counts only publicly reachable HTTPS/HTTP URLs. If you do not have a custom domain or a TLS reverse proxy yet, you can expose your local gateway through a free Cloudflare quick tunnel without creating an account.

bash
npm run gateway                                          # node on port 8080
cloudflared tunnel --url http://127.0.0.1:8080           # in a second terminal
npm run verify:node -- https://…trycloudflare.com        # check the public address

The tunnel prints a temporary *.trycloudflare.com URL: it changes every time the tunnel process restarts. For a permanent node, set up TLS on your own domain with Caddy — docs/DEPLOY.md.

Status in the official MCP Registry

OpenSMM is not listed in the official MCP Registry, and that is the expected result: GET https://registry.modelcontextprotocol.io/v0/servers?search=opensmm answers {"servers":[],"metadata":{"count":0}}.

Schema 2025-12-11 accepts a server only with a published package (packages[] carrying registryType and identifier) or with remotes pointing at a public hosted endpoint. OpenSMM has neither: no package is published, the container image stays private, and there is no public hosted MCP endpoint. Inventing packages or remotes is not allowed.

A published package or a public hosted MCP endpoint would change this. Until then the node is installed from source — “Run a node from source in 5 minutes” in the README.

Honest limits

  1. No MCP Registry entry yet: without a published package or a public hosted endpoint the registry does not accept a server, and inventing packages or remotes is not allowed.
  2. A local node serves a mock catalog (synthetic: true), not real supply.
  3. The census counts only publicly reachable URLs: a localhost node is checked locally but never enters the census.
