Order SMM services from a LlamaIndex agent

LlamaIndex reaches an OpenSMM node in two ways. The first is McpToolSpec with BasicMCPClient from llama-index-tools-mcp: it connects to the node's POST /mcp endpoint and turns every tool the node advertises into a LlamaIndex FunctionTool for an agent or a workflow. The second is three native FunctionTool functions that call REST /v0 with the Python standard library. Both are on this page, and both were run against the mock node from step 1 with llama-index-core 0.14.26 and llama-index-tools-mcp 0.7.0. Every service in that catalog is synthetic: true, orders stay REQUIRES_PAYMENT and nothing is paid.

1. Start the node (about 2 minutes)

You need Node.js ≥ 22.18. One process serves REST /v0 and MCP /mcp on the same port.

bash
git clone https://github.com/opensmm-protocol/mcp-server.git
cd mcp-server
npm ci
PORT=8080 npm run gateway

The node prints gateway listening on http://localhost:8080 (REST /v0, MCP /mcp; provider: mock, mock catalog — not real supply) on stderr. Check it from another terminal: curl -s http://127.0.0.1:8080/v0/services | head -30 — every service carries "synthetic": true. Port taken? PORT=8081 npm run gateway and use that address everywhere below. Other startup fixes: node startup failures. A Docker Compose alternative to the four commands is in deploying an OpenSMM node.

2. Install the LlamaIndex packages

The versions below are the ones this page was run with: llama-index-core 0.14.26 and llama-index-tools-mcp 0.7.0, which brings the Python mcp client (mcp 2.3.0). They need Python 3.11 or newer, below 4.0.

bash
python3 -m venv .venv
. .venv/bin/activate
pip install "llama-index-core==0.14.26" "llama-index-tools-mcp==0.7.0"

The node from step 1 needs no credentials and no Python: the gateway is a separate process, and the agent talks to it over HTTP.

3. Route A: the node's MCP tools as LlamaIndex tools

BasicMCPClient takes the node's MCP URL and picks the streamable HTTP transport for an http or https URL. McpToolSpec wraps that client and converts every tool the node advertises into a FunctionTool. On this node the adapter lists eleven tools — get_capabilities, list_providers, search_services, compare_offers, get_service, get_quote, create_order, get_order_status and the rest; the order flow uses three of them.

python — list the node's tools
import asyncio

from llama_index.tools.mcp import BasicMCPClient, McpToolSpec


async def main():
    spec = McpToolSpec(client=BasicMCPClient("http://127.0.0.1:8080/mcp"))
    tools = await spec.to_tool_list_async()
    for tool in tools:
        print(tool.metadata.get_name())


asyncio.run(main())

Expected output: eleven names, starting with get_capabilities and ending with request_refill. Pass allowed_tools=["search_services", "get_quote", "create_order", "get_order_status"] to McpToolSpec when the agent should see only the order flow.

A tool call returns a LlamaIndex ToolOutput; its raw_output is the MCP CallToolResult, so the node's JSON sits in raw_output.content[0].text. The run below does the whole order flow without an LLM — this is the part that was executed for this page:

python — catalog, quote, order and a replay
import asyncio
import json

from llama_index.tools.mcp import BasicMCPClient, McpToolSpec

LINK = "https://t.me/opensmm_example"


def payload(result) -> dict:
    return json.loads(result.raw_output.content[0].text)


async def main():
    spec = McpToolSpec(client=BasicMCPClient("http://127.0.0.1:8080/mcp"))
    tools = {tool.metadata.get_name(): tool for tool in await spec.to_tool_list_async()}

    catalog = payload(await tools["search_services"].acall(
        query="telegram members",
        platform="telegram",
        objective="members",
        sort="relevance",
    ))
    service_id = catalog["services"][0]["serviceId"]

    quote = payload(await tools["get_quote"].acall(
        serviceId=service_id,
        quantity=100,
        link=LINK,
        parameters={},
    ))

    order = payload(await tools["create_order"].acall(
        quoteId=quote["quoteId"],
        link=LINK,
        quantity=100,
        parameters={},
        clientReference="llamaindex-mcp-1",
    ))

    replay = payload(await tools["create_order"].acall(
        quoteId=quote["quoteId"],
        link=LINK,
        quantity=100,
        parameters={},
        clientReference="llamaindex-mcp-1",
    ))

    print(order["orderId"], order["paymentStatus"])
    print("replay returns the same order:", replay["orderId"] == order["orderId"])


asyncio.run(main())

Expected output: osmm_order_... REQUIRES_PAYMENT and replay returns the same order: True. The identifiers change on every run. Unlike some MCP adapters, this one sends only the arguments you pass: an omitted optional argument is left out of the call instead of being sent as null, and search_services with no arguments returns the whole mock catalog (six services).

4. Route B: three native tools over REST

If you would rather not add the MCP client, the same flow is three plain Python functions wrapped in FunctionTool, calling the node's REST endpoints. Only the standard library is used for HTTP — urllib and json. Save this as opensmm_tools.py:

python — opensmm_tools.py
"""LlamaIndex tools for an OpenSMM node. Standard library only: urllib + json."""
import json
import urllib.error
import urllib.parse
import urllib.request

from llama_index.core.tools import FunctionTool

BASE_URL = "http://127.0.0.1:8080"


def _request(method, path, payload=None):
    data = json.dumps(payload).encode("utf-8") if payload is not None else None
    request = urllib.request.Request(
        BASE_URL + path,
        data=data,
        headers={"content-type": "application/json"},
        method=method,
    )
    try:
        with urllib.request.urlopen(request, timeout=15) as response:
            return json.load(response)
    except urllib.error.HTTPError as err:
        if err.code == 402:  # an unpaid order still carries the order body
            return json.load(err)
        raise


def search_smm_services(query: str) -> str:
    """Search the node's service catalog. Example query: 'telegram members'."""
    catalog = _request("GET", "/v0/services?query=" + urllib.parse.quote(query))
    return json.dumps(catalog["services"], indent=2)


def quote_smm_service(service_id: str, quantity: int, link: str) -> str:
    """Price a service before ordering. Returns a quoteId valid for 15 minutes."""
    quote = _request(
        "POST",
        "/v0/quotes",
        {"serviceId": service_id, "quantity": quantity, "link": link},
    )
    return json.dumps(quote, indent=2)


def create_smm_order(quote_id: str, link: str, client_reference: str) -> str:
    """Create an order from a quote. One clientReference is one order, even on replay."""
    order = _request(
        "POST",
        "/v0/orders",
        {"quoteId": quote_id, "link": link, "clientReference": client_reference},
    )
    return json.dumps(order, indent=2)


search_tool = FunctionTool.from_defaults(fn=search_smm_services)
quote_tool = FunctionTool.from_defaults(fn=quote_smm_service)
order_tool = FunctionTool.from_defaults(fn=create_smm_order)

The tools are plain Python objects, so they can be checked without an LLM:

python — run the three tools
import json

from opensmm_tools import order_tool, quote_tool, search_tool

services = json.loads(search_tool.call(query="telegram members").raw_output)
quote = json.loads(quote_tool.call(
    service_id=services[0]["serviceId"],
    quantity=100,
    link="https://t.me/opensmm_example",
).raw_output)
order = json.loads(order_tool.call(
    quote_id=quote["quoteId"],
    link="https://t.me/opensmm_example",
    client_reference="llamaindex-rest-1",
).raw_output)
print(order["orderId"], order["paymentStatus"])

The last line prints osmm_order_... REQUIRES_PAYMENT; the service the tools return is marked synthetic: True. A second create_smm_order call with the same client_reference returns the same orderId. Here raw_output is the tool's own return value — the JSON string these functions built — which is why the two routes read their results differently.

5. A LlamaIndex workflow: search, quote, order as steps

The same three tools fit a Workflow without any LLM: each step returns an event that carries the identifier the next step needs, and the tool list is kept in the workflow context. This workflow was run against the mock node from step 1:

python — opensmm_workflow.py
import asyncio
import json

from llama_index.core.workflow import (
    Context,
    Event,
    StartEvent,
    StopEvent,
    Workflow,
    step,
)
from llama_index.tools.mcp import BasicMCPClient, McpToolSpec

NODE_URL = "http://127.0.0.1:8080/mcp"
LINK = "https://t.me/opensmm_example"
CLIENT_REFERENCE = "llamaindex-workflow-1"


class ServicesListed(Event):
    service_id: str


class QuoteIssued(Event):
    quote_id: str


def payload(result) -> dict:
    return json.loads(result.raw_output.content[0].text)


class OrderWorkflow(Workflow):
    @step
    async def search(self, ctx: Context, ev: StartEvent) -> ServicesListed:
        spec = McpToolSpec(
            client=BasicMCPClient(NODE_URL),
            allowed_tools=["search_services", "get_quote", "create_order"],
        )
        tools = {
            tool.metadata.get_name(): tool
            for tool in await spec.to_tool_list_async()
        }
        await ctx.store.set("tools", tools)
        catalog = payload(await tools["search_services"].acall(
            query="telegram members",
            platform="telegram",
            objective="members",
            sort="relevance",
        ))
        return ServicesListed(service_id=catalog["services"][0]["serviceId"])

    @step
    async def quote(self, ctx: Context, ev: ServicesListed) -> QuoteIssued:
        tools = await ctx.store.get("tools")
        quote = payload(await tools["get_quote"].acall(
            serviceId=ev.service_id,
            quantity=100,
            link=LINK,
            parameters={},
        ))
        return QuoteIssued(quote_id=quote["quoteId"])

    @step
    async def order(self, ctx: Context, ev: QuoteIssued) -> StopEvent:
        tools = await ctx.store.get("tools")
        order = payload(await tools["create_order"].acall(
            quoteId=ev.quote_id,
            link=LINK,
            quantity=100,
            parameters={},
            clientReference=CLIENT_REFERENCE,
        ))
        return StopEvent(result=order)


async def main():
    order = await OrderWorkflow(timeout=60).run()
    print(order["orderId"], order["paymentStatus"])


asyncio.run(main())

Expected output: osmm_order_... REQUIRES_PAYMENT. A second run answers IDEMPOTENCY_CONFLICT: the workflow requests a fresh quote, and a new quote cannot reuse a stored clientReference. Pick a new CLIENT_REFERENCE for each run, exactly as an agent would.

6. Put the tools on an agent

For a model-driven agent, pass the same tool list to FunctionAgent and let the model decide which tool to call. The wiring below was checked with LlamaIndex's MockLLM — the four allowed tools attach to the agent and their argument schemas resolve; the run itself needs a model of your choice:

python — FunctionAgent on the node's tools
import asyncio

from llama_index.core.agent.workflow import FunctionAgent
from llama_index.llms.openai import OpenAI
from llama_index.tools.mcp import BasicMCPClient, McpToolSpec


async def main():
    spec = McpToolSpec(
        client=BasicMCPClient("http://127.0.0.1:8080/mcp"),
        allowed_tools=["search_services", "get_quote", "create_order", "get_order_status"],
    )
    tools = await spec.to_tool_list_async()

    agent = FunctionAgent(
        tools=tools,
        llm=OpenAI(model="gpt-4.1-mini"),
        system_prompt=(
            "You order SMM services on the OpenSMM mock catalog. Never pay: "
            "leave every order in REQUIRES_PAYMENT."
        ),
    )
    result = await agent.run(
        "Search the catalog for 'telegram members', price the first service for "
        "quantity 100 with link https://t.me/opensmm_example, then create one order "
        "with clientReference llamaindex-agent-1. Report the orderId and paymentStatus."
    )
    print(result)


asyncio.run(main())

The model part is yours, not OpenSMM's: the node calls no LLM and needs no key. llama_index.llms.openai comes from the llama-index-llms-openai package — install it with your key, or swap in any other LlamaIndex LLM. The same tool list works with a Workflow that calls agent.run() as one of its steps.

7. What the tools do

  1. search_services / GET /v0/services — reads the catalog. On the mock node every entry is synthetic: true with providerRef: "provider-alpha": fixtures, not sellable supply.
  2. get_quote / POST /v0/quotes — takes serviceId, quantity, link and returns a quoteId with expiresAt fifteen minutes out and confirmationRequired: true; a quote is consumed once.
  3. create_order / POST /v0/orders — takes quoteId, link and clientReference. Over REST an unpaid order answers HTTP 402 and still carries the order body; the tools above read that body instead of failing.
  4. The replay: the same clientReference with the same quote returns the stored order, so one reference is one order on any transport. Keep the reference to replay an order; for a genuinely new order pick a new one — a new quote with an old reference answers 409.
  5. Status after that: get_order_status / GET /v0/orders/{id}, cancel_order, request_refill.

Protocol-level details — paymentStatus and executionStatus as separate state machines, decimal strings on integer micro-units, canonical error codes: spec/v0.

If something looks wrong

  • KeyError: 'orderId' — a tool error arrives as a normal MCP result with is_error=True and an {"error": {"code": ...}} body, not as an exception. Check for error.code before reading the order fields.
  • AttributeError: 'ToolOutput' object has no attribute ... — read the node's JSON from raw_output.content[0].text on the MCP route; on the REST route raw_output is the string the function returned.
  • RuntimeError: asyncio.run() cannot be called from a running event loop — to_tool_list() is the synchronous wrapper; inside an async app or a notebook cell use await spec.to_tool_list_async().
  • ECONNREFUSED 127.0.0.1:8080 — the node from step 1 is not running, or it listens on another port; change NODE_URL or BASE_URL.
  • IDEMPOTENCY_CONFLICT (HTTP 409) — that clientReference already belongs to an order made from a different quote. Reuse the original quote or pick a new reference.
  • A service is not marked synthetic — stop and do not order: this demo must not place real orders. Restart the node without a provider configured.
  • HTTP 402 on POST /v0/orders is expected, not a failure: the order exists and waits for payment.

Honest limits

  1. There is no ready-made LlamaIndex example in the mcp-server repository — this page is the example. The MCP route, the REST route and the workflow were run against the mock node with llama-index-core 0.14.26, llama-index-tools-mcp 0.7.0 and mcp 2.3.0; a newer release of any of them may change the adapter API.
  2. The catalog is a mock (synthetic: true): no real services and no prices on this page, and nothing is paid or executed.
  3. The agent in step 6 needs an LLM key of your own; its run was not part of what was executed here — only the tool wiring was.
  4. The MCP route exposes all eleven node tools unless allowed_tools narrows them; the model decides when to call them.
  5. Other stacks: CrewAI crews, ElizaOS plugin, a LangChain-style agent, a Python REST client, agent quickstart.
