Order SMM services from a CrewAI agent

A CrewAI crew reaches an OpenSMM node in two ways. The first is MCPServerAdapter from crewai-tools[mcp]: it connects to the node's POST /mcp endpoint and hands the crew the node's MCP tools as CrewAI tools. The second is three native @tool functions that call REST /v0 with the Python standard library. Both are on this page; both were run against the mock node from step 1 with crewai 1.15.44. Every service in that catalog is synthetic: true, orders stay REQUIRES_PAYMENT and nothing is paid.

1. Start the node (about 2 minutes)

You need Node.js ≥ 22.18. One process serves REST /v0 and MCP /mcp on the same port.

bash
git clone https://github.com/opensmm-protocol/mcp-server.git
cd mcp-server
npm ci
PORT=8080 npm run gateway

The node prints gateway listening on http://localhost:8080 (REST /v0, MCP /mcp; provider: mock, mock catalog — not real supply) on stderr. Check it from another terminal: curl -s http://127.0.0.1:8080/v0/services | head -30 — every service carries "synthetic": true. Port taken? PORT=8081 npm run gateway and use that address everywhere below. Other startup fixes: node startup failures. A Docker Compose alternative to the four commands is in deploying an OpenSMM node.

2. Install the CrewAI packages

The versions below are the ones this page was run with: crewai 1.15.44, crewai-tools 1.15.44 and the mcp extra, which brings mcpadapt and the Python MCP client. They need Python 3.10–3.13.

bash
python3 -m venv .venv
. .venv/bin/activate
pip install "crewai==1.15.44" "crewai-tools[mcp]==1.15.44"

The node from step 1 needs no credentials and no Python: the gateway is a separate process, and the crew talks to it over HTTP.

3. Route A: the node's MCP tools as CrewAI tools

MCPServerAdapter starts the MCP session and adapts every tool the node advertises. The transport comes from the transport key: streamable-http for the node's POST /mcp, or sse. On this node the adapter lists eleven tools — get_capabilities, list_providers, search_services, compare_offers, get_service, get_quote, create_order, get_order_status and the rest; the order flow uses three of them.

python — crew with the node's MCP tools
from crewai import Agent, Crew, Process, Task
from crewai_tools.adapters.mcp_adapter import MCPServerAdapter

server = {"url": "http://127.0.0.1:8080/mcp", "transport": "streamable-http"}

with MCPServerAdapter(server) as opensmm:
    runner = Agent(
        role="SMM order runner",
        goal="Search the OpenSMM catalog and place one demo order",
        backstory="Works on the mock catalog only; never pays, nothing is executed.",
        tools=list(opensmm),
    )
    task = Task(
        description=(
            "Call search_services with query 'telegram members', platform 'telegram', "
            "objective 'members', sort 'relevance'. Take the first serviceId and call "
            "get_quote with quantity 100, link https://t.me/opensmm_example, parameters {}. "
            "Then call create_order with that quoteId, link https://t.me/opensmm_example, "
            "quantity 100, parameters {} and clientReference crewai-demo-1. Repeat the same "
            "create_order call once. Report both orderIds and the paymentStatus."
        ),
        expected_output="Both orderIds, which must be identical, and paymentStatus REQUIRES_PAYMENT.",
        agent=runner,
    )
    Crew(agents=[runner], tasks=[task], process=Process.sequential).kickoff()

kickoff() runs the crew's LLM, so it needs a model key of your choice (OPENAI_API_KEY or any LiteLLM-supported provider). That model is yours, not OpenSMM's: the node calls no LLM. To check the connection and the order flow without any key, call the adapted tools directly — this is the part that was run for this page:

python — the same tools without a crew kickoff
import json
from crewai_tools.adapters.mcp_adapter import MCPServerAdapter

server = {"url": "http://127.0.0.1:8080/mcp", "transport": "streamable-http"}

with MCPServerAdapter(server) as tools:
    by_name = {tool.name: tool for tool in tools}
    catalog = json.loads(
        by_name["search_services"].run(
            query="telegram members",
            platform="telegram",
            objective="members",
            sort="relevance",
        )
    )
    service_id = catalog["services"][0]["serviceId"]
    quote = json.loads(
        by_name["get_quote"].run(
            serviceId=service_id,
            quantity=100,
            link="https://t.me/opensmm_example",
            parameters={},
        )
    )
    order = json.loads(
        by_name["create_order"].run(
            quoteId=quote["quoteId"],
            link="https://t.me/opensmm_example",
            quantity=100,
            parameters={},
            clientReference="crewai-mcp-1",
        )
    )
    print(order["orderId"], order["paymentStatus"])

Expected output: osmm_order_... REQUIRES_PAYMENT. The identifiers change on every run. One caveat of this adapter: it fills every argument the tool schema declares, and omitted optional arguments reach the node as null, which the node rejects (MCP error -32602 ... expected string, received null). Pass all of them, and use parameters={} for object fields.

4. Route B: three native CrewAI tools over REST

If you would rather not add the MCP extra, the same flow is three @tool functions on the node's REST endpoints. Only the standard library is used for HTTP — urllib and json. Save this as opensmm_tools.py:

python — opensmm_tools.py
"""CrewAI tools for an OpenSMM node. Standard library only: urllib + json."""
import json
import urllib.error
import urllib.parse
import urllib.request

from crewai.tools import tool

BASE_URL = "http://127.0.0.1:8080"


def _request(method, path, payload=None):
    data = json.dumps(payload).encode("utf-8") if payload is not None else None
    request = urllib.request.Request(
        BASE_URL + path,
        data=data,
        headers={"content-type": "application/json"},
        method=method,
    )
    try:
        with urllib.request.urlopen(request, timeout=15) as response:
            return json.load(response)
    except urllib.error.HTTPError as err:
        if err.code == 402:  # an unpaid order still carries the order body
            return json.load(err)
        raise


@tool("search_smm_services")
def search_smm_services(query: str) -> str:
    """Search the node's service catalog. Example query: 'telegram members'."""
    catalog = _request("GET", "/v0/services?query=" + urllib.parse.quote(query))
    return json.dumps(catalog["services"], indent=2)


@tool("quote_smm_service")
def quote_smm_service(service_id: str, quantity: int, link: str) -> str:
    """Price a service before ordering. Returns a quoteId valid for 15 minutes."""
    quote = _request(
        "POST",
        "/v0/quotes",
        {"serviceId": service_id, "quantity": quantity, "link": link},
    )
    return json.dumps(quote, indent=2)


@tool("create_smm_order")
def create_smm_order(quote_id: str, link: str, client_reference: str) -> str:
    """Create an order from a quote. One clientReference is one order, even on replay."""
    order = _request(
        "POST",
        "/v0/orders",
        {"quoteId": quote_id, "link": link, "clientReference": client_reference},
    )
    return json.dumps(order, indent=2)

The tools are plain Python objects, so they can be checked without an LLM:

python — run the three tools
import json

from opensmm_tools import create_smm_order, quote_smm_service, search_smm_services

services = json.loads(search_smm_services.run(query="telegram members"))
quote = json.loads(
    quote_smm_service.run(
        service_id=services[0]["serviceId"],
        quantity=100,
        link="https://t.me/opensmm_example",
    )
)
order = json.loads(
    create_smm_order.run(
        quote_id=quote["quoteId"],
        link="https://t.me/opensmm_example",
        client_reference="crewai-1",
    )
)
print(order["orderId"], order["paymentStatus"])

The last line prints osmm_order_... REQUIRES_PAYMENT; the service the tools return is marked synthetic: True. A second create_smm_order call with the same client_reference returns the same orderId. To give the tools to a crew, list them on the agent — tools=[search_smm_services, quote_smm_service, create_smm_order] — and describe the flow in the task:

python — the crew
from crewai import Agent, Crew, Process, Task

from opensmm_tools import create_smm_order, quote_smm_service, search_smm_services

order_runner = Agent(
    role="SMM order runner",
    goal="Search the catalog, price one service and place a single demo order",
    backstory="Works on the OpenSMM mock catalog only; nothing is paid or executed.",
    tools=[search_smm_services, quote_smm_service, create_smm_order],
)
task = Task(
    description=(
        "Search the catalog for 'telegram members', price the first service for "
        "quantity 100 with link https://t.me/opensmm_example, then create one order "
        "with clientReference crewai-demo-1. Report the orderId and paymentStatus."
    ),
    expected_output="The orderId and its paymentStatus.",
    agent=order_runner,
)
Crew(agents=[order_runner], tasks=[task], process=Process.sequential).kickoff()

5. What the tools do

  1. search_services / GET /v0/services — reads the catalog. On the mock node every entry is synthetic: true with providerRef: "provider-alpha": fixtures, not sellable supply.
  2. get_quote / POST /v0/quotes — takes serviceId, quantity, link and returns a quoteId that expires in 15 minutes and is consumed once.
  3. create_order / POST /v0/orders — takes quoteId, link and clientReference. Over REST an unpaid order answers HTTP 402 and still carries the order body; the tools above read that body instead of failing.
  4. The replay: the same clientReference with the same quote returns the stored order, so one reference is one order on any transport. Keep the reference to replay an order; for a genuinely new order pick a new one — a new quote with an old reference answers 409.
  5. Status after that: get_order_status / GET /v0/orders/{id}, cancel_order, request_refill.

Protocol-level details — paymentStatus and executionStatus as separate state machines, decimal strings on integer micro-units, canonical error codes: spec/v0.

If something looks wrong

  • MCP error -32602 ... expected string, received null — the MCP adapter sent null for an omitted argument. Pass every argument the tool lists: query, platform, objective, sort for search_services, parameters={} for object fields.
  • ECONNREFUSED 127.0.0.1:8080 — the node from step 1 is not running, or it listens on another port; change BASE_URL or the url in server.
  • IDEMPOTENCY_CONFLICT (HTTP 409) — that clientReference already belongs to an order made from a different quote. Reuse the original quote or pick a new reference.
  • A service is not marked synthetic — stop and do not order: this demo must not place real orders. Restart the node without a provider configured.
  • HTTP 402 on POST /v0/orders is expected, not a failure: the order exists and waits for payment.

Honest limits

  1. There is no ready-made CrewAI example in the mcp-server repository — this page is the example. Both routes were run against the mock node with crewai 1.15.44 and crewai-tools 1.15.44; a newer release of either package may change the adapter API.
  2. The catalog is a mock (synthetic: true): no real services and no prices on this page, and nothing is paid or executed.
  3. kickoff() needs an LLM key for the crew; the node itself needs no key, account or money.
  4. The MCP route exposes all eleven node tools to the crew, not just the three used here; the model decides when to call them.
  5. Other stacks: ElizaOS plugin, a LangChain-style agent, a Python REST client, agent quickstart.
