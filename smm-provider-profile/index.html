Профиль подключения SMM-панели

Профиль — это данные, которыми узел OpenSMM описывает вашу панель: baseUrl, apiKey, профиль поведения и адрес выплат. Код интеграции писать не нужно.

Из чего состоит профиль

  • adapter — диалект API панели: smm-v2 (классический key + action) или rest-v1 (GET /services, POST /orders, Bearer-авторизация).
  • endpoint / baseUrl — публичный https://-URL API панели (защита от SSRF, spec/v0 §10.2).
  • apiKey — ключ панели. Используется только для вызовов вашего API, не возвращается протоколом, не логируется и не показывается в списках.
  • profile (только smm-v2) — чем API панели отличается от классической формы: поле авторизации, конверт ответа, псевдонимы полей.
  • payoutAddress — адрес USDC на Base для прямых выплат (необязателен, но рекомендован).

Как получить профиль

Доктор — проверка только на чтение: HTTPS и JSON против HTML/Cloudflare, action=balance, action=services, конверт и псевдонимы полей. Ничего не регистрируется, ключ не печатается. В отчёте — предложенное имя профиля и готовый сниппет подключения.

bash
OPENSMM_PANEL_KEY="<panel api key>" npm run doctor -- --url https://your-panel.example/api/v2

Код выхода 0 — все проверки прошли, 1 — отчёт называет проваленную проверку. Доктор говорит только на smm-v2; для rest-v1 аналогичная проверка — healthcheck гейтвея при регистрации.

Зарегистрировать панель

bash
curl -X POST http://localhost:8080/v0/providers \
  -H 'content-type: application/json' \
  -d '{
    "adapter": "smm-v2",
    "endpoint": "https://your-panel.example/api/v2",
    "apiKey": "<panel api key>",
    "profile": "<profile from the doctor report>",
    "payoutAddress": "0xYourUsdcAddressOnBase"
  }'

Повторная регистрация того же endpoint идемпотентна — вы получите тот же providerKey. Готовый шаблон с плейсхолдерами для rest-v1: examples/provider-profile.example.json. Заполненный файл — секрет: держите его вне git и чатов.

Честные ограничения

  1. Пакет npm ещё не опубликован: установка из чекаута репозитория.
  2. Узел вы запускаете и обслуживаете сами; у него нет своего TLS и аутентификации — см. docs/DEPLOY.md.
  3. Платежи x402 проверяются на USDC Base Sepolia — testnet.
  4. Публичный каталог — демонстрация (mock-фикстуры с synthetic: true), пока первая панель не подключена.
