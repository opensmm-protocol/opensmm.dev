Оплата SMM-заказов агентом по x402 (testnet)

Как агент оплачивает заказ по x402: от кошелька до тестового платежа. Только testnet — USDC в Base Sepolia, боевая оплата не включена.

1. Что это и что не обещано

Оплата заказа агентом идёт по x402: сервер отвечает HTTP 402 с требованием оплаты, агент подписывает перевод USDC, фасилитатор проводит расчёт. Сейчас это только testnet — USDC в сети Base Sepolia. Боевая оплата не включена.

  • Без переменных окружения x402 шлюз остаётся на dev-only mock-рельсе — для локальной разработки и тестов ничего не меняется;
  • mainnet-USDC пока не включён, реальные деньги через этот путь не проходят;
  • деньги идут по прямому расчёту «агент → провайдер» и не проходят через шлюз.

2. Кошелёк-получатель

Скрипт создаёт кошелёк и дописывает в .env (chmod 600, в gitignore) три переменные; приватный ключ не печатается и не коммитится.

bash
node scripts/create-wallet.ts

# .env
X402_NETWORK=eip155:84532
X402_PAYTO_ADDRESS=0x...   # адрес получателя шлюза
X402_PRIVATE_KEY=0x...     # не печатается и не коммитится

Для первой пробы один кошелёк может быть и плательщиком, и получателем (перевод самому себе — валидный EIP-3009). Для реалистичного потока возьмите второй кошелёк плательщика.

3. Тестовые USDC и фасилитатор

Плательщику нужны тестовые USDC в Base Sepolia — их выдаёт бесплатный кран Circle (faucet.circle.com). ETH плательщику не нужен: для схемы exact газ transferWithAuthorization оплачивает фасилитатор.

bash
X402_FACILITATOR_URL=https://x402.org/facilitator

Это публичный тестовый фасилитатор без авторизации. Боевые фасилитаторы (например Coinbase CDP) требуют ключ API. После запуска GET /v0/capabilities показывает paymentMethods: ["x402"], а расчёт через method: "mock" в этой конфигурации отклоняется.

4. Тестовый платёж

Один скрипт проходит весь путь с реальной testnet-рельсой: котировка → заказ → 402 → расчёт → старт исполнения.

bash
npm run x402:testnet
  • котировка минимального количества у стандартной услуги mock-каталога;
  • заказ и чтение требования оплаты x402;
  • подпись EIP-3009 transferWithAuthorization ключом X402_PRIVATE_KEY;
  • отправка через фасилитатор: /verify, затем /settle;
  • печать хэша транзакции и статуса исполнения.

Каталог при этом mock (synthetic: true), а не реальное предложение. Полная инструкция — docs/X402_TESTNET.md.

Если расчёт не прошёл

  • отказ фасилитатора (плохая подпись, нехватка баланса) — PAYMENT_REQUIRED с причиной, заказ остаётся в REQUIRES_PAYMENT;
  • settlement_pending — заказ переходит в SETTLEMENT_PENDING с хэшем транзакции: сверьте по сети и не платите повторно;
  • HTTP 5xx или таймаут фасилитатора — обычная ошибка, платёж можно повторить.

Честные ограничения

  1. Это testnet: USDC в Base Sepolia, боевая оплата не включена.
  2. Каталог — mock-фикстуры, а не реальное предложение.
  3. Пакет npm и публичный образ не опубликованы: команды запускаются из чекаута репозитория.
