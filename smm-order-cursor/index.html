Заказ SMM-услуги из Cursor

Cursor подключается к запущенному узлу OpenSMM по Streamable HTTP: конфиг .cursor/mcp.json указывает на POST /mcp гейтвея. Проброс портов и учётные данные не нужны. Всё идёт на mock-каталоге: каждая услуга помечена synthetic: true, заказы остаются в статусе REQUIRES_PAYMENT и не оплачиваются.

1. Поднять узел (около 2 минут)

Нужны Node.js ≥ 22.18 и сборка Cursor с поддержкой MCP: конфигурация mcpServers с полем url, протокол MCP 2025-06-18.

bash
git clone https://github.com/opensmm-protocol/mcp-server.git
cd mcp-server
npm ci
npm run gateway

Узел печатает на stderr строку вида gateway listening on http://localhost:8080 (REST /v0, MCP /mcp; provider: mock, mock catalog — not real supply). Порт занят? PORT=8081 npm run gateway и тот же адрес в mcp.json. Другие сбои запуска — сбои запуска узла.

2. Подключить Cursor

Скопируйте .cursor/mcp.json из examples/cursor/ в свой проект или влейте запись mcpServers.opensmm в глобальный конфиг MCP Cursor.

json
{
  "mcpServers": {
    "opensmm": {
      "url": "http://127.0.0.1:8080/mcp"
    }
  }
}

URL обязан заканчиваться на /mcp. Перезагрузите Cursor и убедитесь, что в списке появились инструменты opensmm: search_services, get_quote, create_order.

3. Что попросить у агента

Откройте новый чат и попросите Cursor пройти сценарий одним запросом:

text
Через инструменты opensmm вызови search_services и подтверди, что каждая
услуга помечена synthetic. Затем вызови get_quote для первой услуги с
количеством 100 и ссылкой https://t.me/opensmm_example, вызови create_order
с этой котировкой и clientReference cursor-demo-1, затем вызови create_order
ещё раз с той же котировкой и тем же референсом. Покажи оба orderId.

Ожидаемый результат:

  • search_services → mock-каталог, у каждой услуги synthetic: true;
  • get_quote → osmm_quote_..., количество 100;
  • первый create_order → osmm_order_..., paymentStatus: REQUIRES_PAYMENT;
  • второй create_order → тот же orderId — один clientReference, один заказ, хотя каждый вызов — отдельный POST /mcp.

Если что-то выглядит неправильно

  • Услуга не помечена synthetic — остановитесь и не заказывайте: демо не должно заказывать реальное предложение. Заказ не оплачивается, значит ничего не исполняется.
  • ECONNREFUSED — узел из шага 1 не запущен или слушает другой порт.
  • IDEMPOTENCY_CONFLICT — этот clientReference уже принадлежит заказу из другой котировки: передайте исходную или возьмите новый референс.
  • HTTP 402 на POST /v0/orders — ожидаемый ответ, а не сбой.
