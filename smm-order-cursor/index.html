Order SMM services from Cursor

Cursor connects to a running OpenSMM node over Streamable HTTP: the .cursor/mcp.json config points at the gateway's POST /mcp endpoint. No port forwarding, no credentials. Everything runs on the mock catalog: every service is marked synthetic: true, orders stay REQUIRES_PAYMENT and are never paid.

1. Start the node (about 2 minutes)

You need Node.js ≥ 22.18 and a Cursor build with MCP support: the mcpServers config shape with a url field, MCP protocol 2025-06-18.

bash
git clone https://github.com/opensmm-protocol/mcp-server.git
cd mcp-server
npm ci
npm run gateway

The node prints a line like gateway listening on http://localhost:8080 (REST /v0, MCP /mcp; provider: mock, mock catalog — not real supply) on stderr. Port taken? PORT=8081 npm run gateway and use that address in mcp.json. Other startup fixes: node startup failures.

2. Connect Cursor

Copy .cursor/mcp.json from examples/cursor/ into your project, or merge its mcpServers.opensmm entry into your global Cursor MCP config.

json
{
  "mcpServers": {
    "opensmm": {
      "url": "http://127.0.0.1:8080/mcp"
    }
  }
}

The URL must end in /mcp. Reload Cursor and confirm the opensmm tools are listed: search_services, get_quote, create_order.

3. What to ask the agent

Open a new chat and ask Cursor to run the whole scenario in one prompt:

text
Using the opensmm tools, call search_services and confirm every service
is synthetic. Then call get_quote for the first service with quantity 100
and link https://t.me/opensmm_example, call create_order with that quote
and clientReference cursor-demo-1, then call create_order again with the
same quote and reference. Report both order IDs.

Expected result:

  • search_services → the mock catalog, every service synthetic: true;
  • get_quote → osmm_quote_..., quantity 100;
  • first create_order → osmm_order_..., paymentStatus: REQUIRES_PAYMENT;
  • second create_order → the same orderId — one clientReference, one order, even though each call is a separate POST /mcp.

If something looks wrong

  • A service is not marked synthetic — stop, do not order: this demo must not order real supply. The order is never paid, so nothing executes.
  • ECONNREFUSED — the node from step 1 is not running or uses another port.
  • IDEMPOTENCY_CONFLICT — that clientReference already belongs to an order made from a different quote: pass the original or use a new reference.
  • HTTP 402 on POST /v0/orders is expected, not a failure.
