Order an SMM service from an agent in 5 minutes

A short guide for agent developers. Everything runs on a local node and its mock catalog: every service is marked synthetic: true, no real order is executed, and no key, account or money is needed. Orders stay REQUIRES_PAYMENT and are never paid.

1. Start the node (about 2 minutes)

Node.js ≥ 22.18 is required.

bash
git clone https://github.com/opensmm-protocol/mcp-server.git
cd mcp-server
npm ci
npm run gateway

The node prints a line like gateway listening on http://localhost:8080 (REST /v0, MCP /mcp; provider: mock, mock catalog — not real supply) on stderr. Check from another terminal: curl -s http://127.0.0.1:8080/v0/services | head -30 — every service has "synthetic": true. Port taken? PORT=8081 npm run gateway. Other startup fixes: node startup failures.

2. Pick your stack

Each stack has a ready config or script in the repository; every directory has its own README with the exact steps and expected output.

3. Run one example (about 2 minutes)

The fastest path with no third-party app is the LangChain-style tool caller.

bash
node examples/langchain/agent.mjs http://127.0.0.1:8080 --client-reference my-first-order
text
node:      http://127.0.0.1:8080
transport: MCP tools over POST /mcp (LangChain-style tool calls)
tools:     search_services, get_quote, create_order
tool:      search_services({})
catalog:   MOCK — every service is marked synthetic: not real supply, no real money
service:   osmm_svc_tg_members_std — Telegram Channel Members — Standard
quote:     osmm_quote_... — 0.241200 USDC for 100 (mock rate)
order:     osmm_order_... — REQUIRES_PAYMENT, clientReference "my-first-order"
replay:    osmm_order_... — same orderId, no second order created
done:      LangChain-style agent OK

That is the whole scenario: catalog → quote → order → replay. order: and replay: are the same orderId: the same clientReference yields one order on any transport.

4. What the agent actually called

  1. search_services — reads the catalog; every entry carries synthetic: true, and the examples refuse to continue if a service is not marked mock.
  2. get_quote — prices one service for quantity 100 and a link. A quote is consumed once, so each order needs its own.
  3. create_order — creates an unpaid order (HTTP 402 over REST, still carrying the order body). Nothing is paid, nothing executes.
  4. create_order again with the same clientReference — a replay that returns the stored order instead of creating a second one.

REST equivalents: GET /v0/services, POST /v0/quotes, POST /v0/orders, and GET /v0/orders/:id to poll.

5. If something looks wrong

  • is not marked synthetic — the node is not on its mock catalog; stop, do not order. Restart it without a provider configured.
  • ECONNREFUSED — the node from step 1 is not running or uses another port.
  • IDEMPOTENCY_CONFLICT — that clientReference already belongs to an order made from a different quote: pass the original via --quote or use a new reference.
  • HTTP 402 on POST /v0/orders is expected, not a failure.

Honest limits
