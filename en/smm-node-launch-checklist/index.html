OpenSMM node launch checklist

Six steps from a checkout to a node the census will count. Every step can be checked with a command.

1. Prepare

You need Node.js ≥ 22.18 and git. No keys and no external services: the node boots on the built-in mock catalog.

bash
node --version   # v22.18 or newer
git clone https://github.com/opensmm-protocol/mcp-server.git
cd mcp-server
npm ci

There is no npm package and no public image: a repository checkout is the install.

2. Start

One process: REST /v0 and MCP /mcp on one port (default 8080).

bash
PORT=8080 OPENSMM_STATE_FILE=./opensmm-state.json npm run gateway

With OPENSMM_STATE_FILE orders, metrics and registered nodes survive a restart. The node prints its port on stderr at start.

3. Check locally

Before reporting, run the same two probes the census uses: GET /v0/services and MCP initialize.

bash
curl -s http://127.0.0.1:8080/health
npm run verify:node -- http://127.0.0.1:8080

Exit code 0 and a PASS verdict mean the census would count the node. Node definition: docs/NODES.md. Startup failures: node startup failures.

4. Public URL

The census counts only publicly reachable URLs. The node has no TLS and no authentication of its own, so expose it behind a proxy.

  • a permanent node — your own domain and TLS through a reverse proxy (for example Caddy: reverse_proxy 127.0.0.1:8080), node port on loopback only;
  • a quick test without a domain — a free Cloudflare quick tunnel: cloudflared tunnel --url http://127.0.0.1:8080; the URL is temporary and changes on every restart;
  • OPENSMM_TRUST_PROXY=1 only when the proxy overwrites x-forwarded-for.
bash
npm run verify:node -- https://your-url

The census does not follow redirects — use the final URL. TLS details: docs/DEPLOY.md, deploying a node.

5. Payout address

So that the orders of your node carry your payout address, set OPENSMM_PROVIDER_PAYOUT before you publish the node.

Direct settlement is canonical: an order carries x402 payment requirements with the provider's address as payTo; the gateway never holds funds. Payment is testnet only, see paying over x402.

6. Report the node

A node that passes the check on a public URL is reported through an issue template in the repository.

  • issues/new?template=node-report.md — one node URL;
  • once a week the census checks reported URLs with the same two probes;
  • for monitoring: npm --silent run verify:node -- --json <url> prints JSON, exit code 1 means the node is not counted.

Honest limits

  1. The npm package and a public image are not published: the node is built from a checkout.
  2. A local node serves a mock catalog (synthetic: true) — fixtures, not real supply and not sellable services.
  3. A live provider is connected as a separate step through OPENSMM_REST_V1_*.
