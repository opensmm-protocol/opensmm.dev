Order SMM services from Claude Code

There is no ready-made example for Claude Code in the mcp-server repo yet — no invented config or code here. An OpenSMM node exposes the same MCP tools used by the Claude Desktop and Cursor examples; this page honestly points to the nearest working example in examples/ and docs/AGENT_QUICKSTART.md. Everything runs on the mock catalog: every service is marked synthetic: true, orders stay REQUIRES_PAYMENT and are never paid — no key, account or money needed.

1. Start a node (about 2 minutes)

You need Node.js ≥ 22.18. Start a node with the mock catalog — it serves REST /v0 and MCP /mcp.

bash
git clone https://github.com/opensmm-protocol/mcp-server.git
cd mcp-server
npm ci
npm run gateway

The node prints a line like gateway listening on http://localhost:8080 (REST /v0, MCP /mcp; provider: mock, mock catalog — not real supply) on stderr. Check from another terminal: curl -s http://127.0.0.1:8080/v0/services | head -30 — every service has "synthetic": true. Port taken? PORT=8081 npm run gateway. Other startup issues: node startup failures.

2. How to wire the MCP server

examples/README.md ships ready MCP server config blocks for stdio and HTTP. They are documented as working with any MCP client; the exact Claude Code command syntax is in the Claude Code docs, not in this repo.

json — stdio (npm run mcp)
{
  "mcpServers": {
    "opensmm": {
      "command": "npm",
      "args": ["run", "mcp"],
      "cwd": "/path/to/mcp-server"
    }
  }
}
json — HTTP (POST /mcp of a running node)
{
  "mcpServers": {
    "opensmm": {
      "url": "http://127.0.0.1:8080/mcp"
    }
  }
}

The config matches mcp.json in the repo root: server io.github.opensmm-protocol/mcp-server, package @opensmm/mcp-server, MCP protocol 2025-06-18. Replace /path/to/mcp-server with the absolute path of your checkout.

3. Nearest working example: catalog → quote → order → replay

To see the whole scenario without Claude Code, run the ready tool-calling script from the quickstart — it calls the same three tools an MCP client in Claude Code would get.

bash
node examples/langchain/agent.mjs http://127.0.0.1:8080 --client-reference my-first-order
text — expected output
transport: MCP tools over POST /mcp (LangChain-style tool calls)
tools:     search_services, get_quote, create_order
catalog:   MOCK — every service is marked synthetic: not real supply, no real money
service:   osmm_svc_tg_members_std — Telegram Channel Members — Standard
quote:     osmm_quote_... — 0.241200 USDC for 100 (mock rate)
order:     osmm_order_... — REQUIRES_PAYMENT, clientReference "my-first-order"
replay:    osmm_order_... — same orderId, no second order created
done:      LangChain-style agent OK

The order: and replay: lines are the same orderId: one clientReference yields one order on any transport. Full walkthrough: docs/AGENT_QUICKSTART.md.

4. What the agent actually called

  1. search_services — reads the catalog; every entry carries synthetic: true. The examples refuse to continue if a service is not marked mock.
  2. get_quote — price one service for quantity 100 and the link https://t.me/opensmm_example. A quote is consumed once, so each order needs its own.
  3. create_order — an unpaid order (HTTP 402 with the order body over REST). Nothing is paid, nothing executes.
  4. create_order again with the same clientReference — the replay returns the stored order instead of creating a second one.

REST equivalents: GET /v0/services, POST /v0/quotes, POST /v0/orders, poll with GET /v0/orders/:id.

If something looks wrong

  • is not marked synthetic — the node is not on its mock catalog; stop, do not order. Restart it without a provider configured.
  • ECONNREFUSED — the node from step 1 is not running or uses another port.
  • IDEMPOTENCY_CONFLICT — that clientReference already belongs to an order made from a different quote; pass the original via --quote or use a new reference.
  • HTTP 402 on POST /v0/orders is expected, not a failure.

Honest limits

  1. There is no dedicated ready example for Claude Code in the repo: the exact wiring syntax is in the Claude Code docs, not on this page.
