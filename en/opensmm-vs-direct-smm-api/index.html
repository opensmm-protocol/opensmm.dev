OpenSMM vs a direct panel API

An agent can order a service straight from a panel or through an OpenSMM node. Here is what changes for an agent developer — per the v0 spec, with no ratings of specific panels.

Two different questions

A panel’s direct API is how one panel accepts an order: POST {endpoint} with key and action (services, add, status and so on), as described in PROVIDER_ONBOARDING.md. OpenSMM is a protocol on top of such panels: the agent talks to a node, and the node talks to the panel through an adapter (smm-v2, rest-v1).

Side by side

  • Who the agent talks to. Direct API: One specific panel: its own endpoint and key each. OpenSMM: An OpenSMM node: the same /v0 commands and MCP tools for any supplier.
  • Order. Direct API: An order is a call to the panel. OpenSMM: A quote first (expires, consumed once), then an order by quoteId.
  • Repeating a request. Direct API: The panel defines the contract — check yours. OpenSMM: clientReference / Idempotency-Key: a replay returns the same orderId; different parameters give IDEMPOTENCY_CONFLICT.
  • Statuses. Direct API: The panel defines the status format. OpenSMM: Two separate state machines: paymentStatus and executionStatus.
  • Ambiguous submission. Direct API: Left to your agent’s code. OpenSMM: SUBMISSION_UNKNOWN: waits for reconciliation, no blind retries to the supplier.
  • Transport. Direct API: The panel’s HTTP. OpenSMM: REST /v0 and MCP /mcp: the same objects.
  • Money. Direct API: Each panel has its own format. OpenSMM: Decimal strings on integer micro-units, never floats.

When the direct API is enough

  • You use one panel and its contract suits you — you do not need a node.
  • You are building an agent that must switch suppliers without rewriting code, or you want uniform idempotency and statuses — use the protocol.
  • You own a panel: connecting is baseUrl + apiKey + a profile, no code, see connect a panel.

MCP versus REST inside the protocol is covered in MCP or REST.

Try it yourself

A local node and mock catalog, no keys, no money. Node.js ≥ 22.18 is required.

bash
git clone https://github.com/opensmm-protocol/mcp-server.git
cd mcp-server
npm ci
npm run gateway
curl -s http://127.0.0.1:8080/v0/services | head -30

Every service has "synthetic": true. The full walkthrough is the agent quickstart.

Honest limits

  1. This page summarises docs/AGENT_QUICKSTART.md; exact versions and configs live there.

  4. The protocol is version 0.1, with no SLA.
