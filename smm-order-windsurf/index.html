Order SMM services from Windsurf

Windsurf (Codeium) reads MCP servers from ~/.codeium/windsurf/mcp_config.json. The opensmm entry below either launches the OpenSMM MCP server as a local child process (npm run mcp over stdio) or points Cascade at the POST /mcp endpoint of a running node. No keys, no accounts, no credentials. Everything runs on the mock catalog: every service is marked synthetic: true, orders stay REQUIRES_PAYMENT and are never paid.

1. Install the node (about 2 minutes)

You need Node.js ≥ 22.18 and a Windsurf build with MCP support: the MCP panel in Cascade settings, MCP protocol 2025-06-18.

bash
git clone https://github.com/opensmm-protocol/mcp-server.git
cd mcp-server
npm ci

The stdio block in step 2 starts the MCP server by itself. The HTTP block also needs a running node: npm run gateway in the same checkout. The node prints a line like gateway listening on http://localhost:8080 (REST /v0, MCP /mcp; provider: mock, mock catalog — not real supply) on stderr. Port taken? PORT=8081 npm run gateway and use that address in mcp_config.json. Other startup fixes: node startup failures.

2. Add the server to mcp_config.json

Open ~/.codeium/windsurf/mcp_config.json — create the file with an empty {} object if it does not exist yet — and add the opensmm entry. On Windows the file is %USERPROFILE%\.codeium\windsurf\mcp_config.json. Pick one of the two blocks: the stdio config is the one in examples/README.md, the remote one is the same server reached at POST /mcp.

json — stdio (npm run mcp)
{
  "mcpServers": {
    "opensmm": {
      "command": "npm",
      "args": ["run", "mcp"],
      "cwd": "/path/to/mcp-server"
    }
  }
}

Replace /path/to/mcp-server with the absolute path of your checkout: npm run mcp runs inside that directory, and the mcp script is in the checkout's package.json by default.

json — HTTP (POST /mcp of a running node)
{
  "mcpServers": {
    "opensmm": {
      "serverUrl": "http://127.0.0.1:8080/mcp"
    }
  }
}

serverUrl is the key Windsurf uses for a server that runs on its own, and the URL must end in /mcp. The OpenSMM node's HTTP binding accepts POST /mcp only and opens no event stream — GET /mcp answers 405. If Cascade reports the remote server as failed, use the stdio block above: the same tools, no port.

Reload the Windsurf window or restart Windsurf, then confirm the opensmm tools are listed: search_services, get_quote, create_order.

3. What to ask the agent

Open a Cascade chat and ask Windsurf to run the whole scenario in one prompt:

text
Using the opensmm tools, call search_services and confirm every service
is synthetic. Then call get_quote for the first service with quantity 100
and link https://t.me/opensmm_example, call create_order with that quote
and clientReference windsurf-demo-1, then call create_order again with the
same quote and reference. Report both order IDs.

Expected result:

  • search_services → the mock catalog, every service synthetic: true;
  • get_quote → osmm_quote_..., quantity 100;
  • first create_order → osmm_order_..., paymentStatus: REQUIRES_PAYMENT;
  • second create_order → the same orderId — one clientReference, one order, even though each call is a separate POST /mcp.

If something looks wrong

  • A service is not marked synthetic — stop, do not order: this demo must not order real supply. The order is never paid, so nothing executes.
  • The opensmm tools did not appear — check cwd (it must be the absolute path of your checkout) and reload the Windsurf window.
  • ECONNREFUSED — the node from step 1 is not running, or uses another port. Only the HTTP block needs it.
  • IDEMPOTENCY_CONFLICT — that clientReference already belongs to an order made from a different quote: pass the original or use a new reference.
  • HTTP 402 on POST /v0/orders is expected, not a failure.

Honest limits

  1. There is no dedicated Windsurf directory in examples/ yet: the stdio block above is the config from examples/README.md, and the file path plus the serverUrl key are the ones Windsurf documents for mcp_config.json.
  2. The scenario for all stacks at once: docs/AGENT_QUICKSTART.md.
  3. The catalog is a mock (synthetic: true): no real services, prices or orders here; orders are not paid in this guide.
  4. Other stacks: agent quickstart, ordering from Cursor, ordering from Claude Desktop.
