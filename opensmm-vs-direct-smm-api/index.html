OpenSMM или прямой API панели

Агенту можно заказывать услугу напрямую у панели или через узел OpenSMM. Разбираем, что меняется для разработчика агента — по спеке v0, без оценок конкретных панелей.

Два разных вопроса

Прямой API панели — это способ одной панели принять заказ: POST {endpoint} с key и action (services, add, status и т. д.), как описано в PROVIDER_ONBOARDING.md. OpenSMM — протокол поверх таких панелей: агент говорит с узлом, а узел через адаптер (smm-v2, rest-v1) говорит с панелью.

Сравнение

  • С кем говорит агент. Прямой API: С конкретной панелью: свой endpoint и свой ключ у каждой. OpenSMM: С узлом OpenSMM: одни команды /v0 и MCP-инструменты для любого поставщика.
  • Заказ. Прямой API: Заказ создаётся вызовом панели. OpenSMM: Сначала котировка (истекает, расходуется один раз), затем заказ по quoteId.
  • Повтор запроса. Прямой API: Контракт задаёт панель — проверьте у своей. OpenSMM: clientReference / Idempotency-Key: повтор возвращает тот же orderId; иной набор параметров — IDEMPOTENCY_CONFLICT.
  • Статусы. Прямой API: Формат статуса задаёт панель. OpenSMM: Два отдельных автомата: paymentStatus и executionStatus.
  • Неясный результат отправки. Прямой API: Решает код вашего агента. OpenSMM: SUBMISSION_UNKNOWN: ждёт сверки, слепых повторов поставщику нет.
  • Транспорт. Прямой API: HTTP панели. OpenSMM: REST /v0 и MCP /mcp: одни и те же объекты.
  • Деньги. Прямой API: Формат у панели свой. OpenSMM: Десятичные строки на целочисленных микроединицах, не float.

Когда хватит прямого API

  • Вы работаете с одной панелью и вас устраивает её контракт — узел вам не нужен.
  • Вы строите агента, который должен менять поставщика без переписывания кода, или хотите единую идемпотентность и статусы — берите протокол.
  • Вы владелец панели: подключение — baseUrl + apiKey + профиль, без кода, см. подключить панель.

Об отличии MCP и REST внутри протокола — MCP или REST.

Попробовать самому

Локальный узел и mock-каталог, без ключей и денег. Нужен Node.js ≥ 22.18.

bash
git clone https://github.com/opensmm-protocol/mcp-server.git
cd mcp-server
npm ci
npm run gateway
curl -s http://127.0.0.1:8080/v0/services | head -30

У каждой услуги "synthetic": true. Полный сценарий — быстрый старт агента.

Честные ограничения

  1. Страница пересказывает docs/AGENT_QUICKSTART.md; точные версии и конфиги — там.
  2. Каталог — mock (synthetic: true): реальных услуг, цен и заказов здесь нет, курс в примерах — тестовый.
  3. Сравнение построено на спеке v0 и документации репозитория; поведение конкретной панели у каждой своё, мы его не оцениваем.
  4. Протокол — версия 0.1, без SLA.
