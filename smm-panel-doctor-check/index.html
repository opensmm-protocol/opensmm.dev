Проверка SMM-панели и узла: doctor

Две проверки до подключения: npm run doctor смотрит API панели, npm run verify:node — ваш узел. Обе безопасны: ничего не регистрируется.

1. Доктор: API панели

Только чтение, диалект smm-v2. Ключ берётся из OPENSMM_PANEL_KEY, а не из аргументов, и никогда не печатается.

bash
OPENSMM_PANEL_KEY="<panel api key>" npm run doctor -- --url https://your-panel.example/api/v2
  • HTTPS и JSON против HTML/Cloudflare;
  • action=balance — баланс и валюта;
  • action=services — непустой каталог и его размер;
  • конверт ответа и псевдонимы полей;
  • предложенное имя профиля и готовый сниппет подключения.

Код выхода 0 — все проверки прошли; 1 — отчёт называет проваленную проверку.

2. Узел: verify:node

Те же две пробы, что использует перепись узлов, — PASS/FAIL по каждой и вердикт. Код выхода 0, если перепись засчитает узел.

bash
npm run verify:node -- http://127.0.0.1:8080
  • GET /v0/services — 200 и JSON-массив services;
  • POST /mcp с initialize — 200 и JSON-RPC result;
  • GET /v0/providers — справочно, на вердикт не влияет.

Для узла за прокси передайте URL, который будет вызывать перепись: редиректы не отслеживаются. Определение узла — docs/NODES.md.

Если что-то не так

Типичные сбои запуска — Node.js ниже 22.18, занятый порт — разобраны в TROUBLESHOOTING.md.

Честные ограничения

  1. Доктор не проверяет создание заказов — только чтение.
  2. Пакет npm ещё не опубликован: команды запускаются из чекаута репозитория.
  3. Локальный узел отдаёт mock-каталог (synthetic: true), а не реальное предложение.

Последний шаг: поднять свой узел

Узел — один процесс, отдающий REST /v0 и MCP /mcp на одном порту. Нужен Node.js ≥ 22.18.
