SMM panel and node check: doctor

Two checks before you connect: npm run doctor inspects your panel API, npm run verify:node inspects your node. Both are safe — nothing is registered.

1. The doctor: your panel API

Read-only, smm-v2 dialect. The key is read from OPENSMM_PANEL_KEY, never from argv, and is never printed.

bash
OPENSMM_PANEL_KEY="<panel api key>" npm run doctor -- --url https://your-panel.example/api/v2
  • HTTPS and JSON vs HTML/Cloudflare;
  • action=balance — balance and currency;
  • action=services — a non-empty catalog and its size;
  • response envelope and field aliases;
  • a suggested profile name and a ready connection snippet.

Exit code 0 — every check passed; 1 — the report names the failed check.

2. The node: verify:node

The same two probes the node census uses — PASS/FAIL per probe and a verdict. Exit code 0 when the census would count the node.

bash
npm run verify:node -- http://127.0.0.1:8080
  • GET /v0/services — 200 with a JSON services array;
  • POST /mcp with initialize — 200 with a JSON-RPC result;
  • GET /v0/providers — informational, never decides the verdict.

For a node behind a proxy, pass the URL the census will call: redirects are not followed. The node definition is in docs/NODES.md.

If something looks wrong

Typical startup failures — Node.js below 22.18, a port already in use — are covered in TROUBLESHOOTING.md.

Honest limitations

  1. The doctor does not test order creation — reads only.
  2. The npm package is not published yet: run the commands from a repository checkout.
  3. A local node serves a mock catalog (synthetic: true), not real supply.

The last step: run your own node

The node is a single process serving REST /v0 and MCP /mcp on one port. You need Node.js ≥ 22.18.
