Чек-лист запуска узла OpenSMM

Шесть шагов от чекаута до узла, который засчитает перепись. Каждый шаг можно проверить командой.

1. Подготовка

Нужен Node.js ≥ 22.18 и git. Ключей и внешних сервисов не нужно: узел стартует на встроенном mock-каталоге.

bash
node --version   # v22.18 или новее
git clone https://github.com/opensmm-protocol/mcp-server.git
cd mcp-server
npm ci

Пакета npm и публичного образа нет: установка — это чекаут репозитория.

2. Запуск

Один процесс: REST /v0 и MCP /mcp на одном порту (по умолчанию 8080).

bash
PORT=8080 OPENSMM_STATE_FILE=./opensmm-state.json npm run gateway

С OPENSMM_STATE_FILE заказы, метрики и зарегистрированные узлы переживают рестарт. Порт узел пишет в stderr при старте.

3. Проверка локально

Перед отчётом прогоните те же две пробы, что использует перепись: GET /v0/services и MCP initialize.

bash
curl -s http://127.0.0.1:8080/health
npm run verify:node -- http://127.0.0.1:8080

Код выхода 0 и вердикт PASS — перепись засчитает узел. Определение узла: docs/NODES.md. Сбои запуска — на странице сбои запуска узла.

4. Публичный адрес

Перепись считает только публично доступные URL. У узла нет TLS и собственной авторизации, поэтому наружу его выставляют за прокси.

  • постоянный узел — свой домен и TLS через обратный прокси (например Caddy: reverse_proxy 127.0.0.1:8080), порт узла только на loopback;
  • быстрая проверка без домена — бесплатный туннель Cloudflare: cloudflared tunnel --url http://127.0.0.1:8080, адрес временный и меняется при каждом перезапуске;
  • OPENSMM_TRUST_PROXY=1 — только если прокси перезаписывает x-forwarded-for.
bash
npm run verify:node -- https://ваш-адрес

Редиректы перепись не проходит — указывайте конечный URL. Разбор TLS: docs/DEPLOY.md, развёртывание узла.

5. Адрес выплат

Чтобы заказы узла несли ваш адрес выплат, задайте OPENSMM_PROVIDER_PAYOUT до публикации узла.

Прямой расчёт — канон протокола: заказ несёт платёжные требования x402 с адресом провайдера как payTo, шлюз средств не держит. Оплата — только в testnet, см. оплата агентом по x402.

6. Отчёт об узле

Узел, прошедший проверку по публичному адресу, сообщают через шаблон задачи в репозитории.

  • issues/new?template=node-report.md — один URL узла;
  • раз в неделю перепись проверяет заявленные URL теми же двумя пробами;
  • для мониторинга: npm --silent run verify:node -- --json <url> печатает JSON, код выхода 1 — узел не засчитан.

Честные ограничения

  1. Пакет npm и публичный образ не опубликованы: узел собирается из чекаута.
  2. Локальный узел отдаёт mock-каталог (synthetic: true) — это фикстуры, не реальное предложение и не продаваемые услуги.
  3. Живой провайдер подключается отдельным шагом через OPENSMM_REST_V1_*.
