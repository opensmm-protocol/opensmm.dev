Заказ SMM-услуги из агента за 5 минут

Короткий гайд для разработчика агента. Всё идёт на локальном узле и его mock-каталоге: каждая услуга помечена synthetic: true, реальный заказ не исполняется, ключ, аккаунт и деньги не нужны. Заказы остаются в статусе REQUIRES_PAYMENT и не оплачиваются.

1. Поднять узел (около 2 минут)

Нужен Node.js ≥ 22.18.

bash
git clone https://github.com/opensmm-protocol/mcp-server.git
cd mcp-server
npm ci
npm run gateway

Узел печатает в stderr строку вида gateway listening on http://localhost:8080 (REST /v0, MCP /mcp; provider: mock, mock catalog — not real supply). Проверка из другого терминала: curl -s http://127.0.0.1:8080/v0/services | head -30 — у каждой услуги "synthetic": true. Порт занят? PORT=8081 npm run gateway. Другие сбои запуска — сбои запуска узла.

2. Выбрать стек

Для каждого стека в репозитории лежит готовый конфиг или скрипт, у каждого каталога свой README с точными шагами и ожидаемым выводом.

text
Claude Desktop      examples/claude-desktop/claude_desktop_config.json   stdio, npm run mcp, порт не нужен
Cursor              examples/cursor/.cursor/mcp.json                    HTTP POST /mcp на узле из шага 1
LangChain-стиль     examples/langchain/agent.mjs                        терминал, ключ LLM не нужен
n8n                 examples/n8n/workflow.json                          импорт workflow, кнопка Execute

3. Запустить один пример (около 2 минут)

Быстрее всего — вызов инструментов в стиле LangChain: сторонние приложения не нужны.

bash
node examples/langchain/agent.mjs http://127.0.0.1:8080 --client-reference my-first-order
text
node:      http://127.0.0.1:8080
transport: MCP tools over POST /mcp (LangChain-style tool calls)
tools:     search_services, get_quote, create_order
tool:      search_services({})
catalog:   MOCK — every service is marked synthetic: not real supply, no real money
service:   osmm_svc_tg_members_std — Telegram Channel Members — Standard
quote:     osmm_quote_... — 0.241200 USDC for 100 (mock rate)
order:     osmm_order_... — REQUIRES_PAYMENT, clientReference "my-first-order"
replay:    osmm_order_... — same orderId, no second order created
done:      LangChain-style agent OK

Сценарий целиком: каталог → котировка → заказ → повтор. Строки order: и replay: — один и тот же orderId: один clientReference даёт один заказ на любом транспорте.

4. Что на самом деле вызвал агент

  1. search_services — читает каталог; у каждой записи synthetic: true, примеры отказываются продолжать, если услуга не помечена как mock.
  2. get_quote — цена одной услуги для количества 100 и ссылки. Котировка расходуется один раз, под каждый заказ нужна своя.
  3. create_order — неоплаченный заказ (по REST — HTTP 402 с телом заказа). Ничего не оплачивается и не исполняется.
  4. create_order ещё раз с тем же clientReference — повтор возвращает сохранённый заказ, а не создаёт второй.

REST-эквиваленты: GET /v0/services, POST /v0/quotes, POST /v0/orders, опрос — GET /v0/orders/:id.

5. Если что-то выглядит неправильно

  • is not marked synthetic — узел не на mock-каталоге; остановитесь и не заказывайте. Перезапустите узел без настроенного провайдера.
  • ECONNREFUSED — узел из шага 1 не запущен или слушает другой порт.
  • IDEMPOTENCY_CONFLICT — этот clientReference уже принадлежит заказу из другой котировки: передайте исходную через --quote или возьмите новый референс.
  • HTTP 402 на POST /v0/orders — ожидаемый ответ, а не сбой.

Честные ограничения

  1. Страница пересказывает docs/AGENT_QUICKSTART.md; версии клиентов и точные конфиги — там.
  2. Каталог — mock (synthetic: true): реальных услуг, цен и заказов здесь нет, курс в примере — тестовый.
  3. Оплата заказа в этом гайде не проходит; про x402 на тестовой сети — оплата агентом по x402.
