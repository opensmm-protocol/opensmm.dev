MCP или REST: заказ SMM-услуг

MCP — один из транспортов протокола OpenSMM, REST /v0 — канонический HTTP-биндинг. Одна и та же операция через оба даёт одни и те же доменные объекты.

Одно правило

Один clientReference → один orderId на любом транспорте. REST передаёт заголовок Idempotency-Key, MCP — поле clientReference. Повтор возвращает тот же заказ; тот же ключ с другими параметрами — IDEMPOTENCY_CONFLICT.

bash
# REST: Idempotency-Key header
curl -X POST http://localhost:8080/v0/orders \
  -H 'content-type: application/json' -H 'Idempotency-Key: my-order-1' \
  -d '{"quoteId":"<quoteId>","link":"https://t.me/example_channel"}'
# MCP: clientReference field of the create_order tool
create_order({"quoteId":"<quoteId>","link":"https://t.me/example_channel","clientReference":"my-order-1"})

Соответствие команд

  • searchServices — GET /v0/services / search_services
  • getQuote — POST /v0/quotes / get_quote
  • createOrder — POST /v0/orders / create_order
  • getOrder — GET /v0/orders/{id} / get_order_status
  • cancelOrder — POST /v0/orders/{id}/cancel / cancel_order
  • requestRefill — POST /v0/orders/{id}/refill / request_refill

Полный список из десяти команд — в SMM API для MCP.

Что выбрать

  • Агент в Claude Desktop, Cursor, LangChain или n8n — MCP: узел отдаёт /mcp (Streamable HTTP, заголовок accept: application/json, text/event-stream).
  • Скрипт, бэкенд или cron — REST /v0: curl и обычный HTTP-клиент.
  • Смешивать можно: заказ, созданный по одному транспорту, виден и опрашивается по другому.

Что одинаково на обоих транспортах

  • Котировка обязательна перед заказом и расходуется ровно один раз.
  • paymentStatus и executionStatus — два отдельных автомата состояний.
  • Создание заказа отвечает HTTP 402 с требованиями оплаты — это ожидаемо, а не ошибка.
  • Деньги — десятичные строки на целочисленных микроединицах, не float.
  • Неоднозначная отправка становится SUBMISSION_UNKNOWN и ждёт сверки — слепых повторов провайдеру нет.

Честные ограничения

  1. Каталог на сайте и у локального узла — mock-фикстуры (synthetic: true), не реальное предложение.
  2. Платежи x402 проверяются на USDC Base Sepolia — testnet.
  3. Протокол — версия 0.1, без SLA.
