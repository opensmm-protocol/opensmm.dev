Order SMM services from Claude Desktop

Claude Desktop talks to an OpenSMM node over stdio: the claude_desktop_config.json config launches the MCP server as a local child process (npm run mcp). No port, no keys, no credentials. Everything runs on the mock catalog: every service is marked synthetic: true, orders stay REQUIRES_PAYMENT and are never paid.

1. Install the node (about 2 minutes)

You need Node.js ≥ 22.18 and a Claude Desktop build with MCP support: the mcpServers config shape, MCP protocol 2025-06-18.

bash
git clone https://github.com/opensmm-protocol/mcp-server.git
cd mcp-server
npm ci

A separate npm run gateway is not needed: the Claude Desktop config starts the MCP server over stdio by itself — the same server that mcp.json in the repo root registers.

2. Copy the config and restart Claude Desktop

Copy claude_desktop_config.json from examples/claude-desktop/ into your Claude Desktop config.

json
{
  "mcpServers": {
    "opensmm": {
      "command": "npm",
      "args": ["run", "mcp"],
      "cwd": "/path/to/mcp-server"
    }
  }
}

Where it goes: macOS — ~/Library/Application Support/Claude/claude_desktop_config.json, Windows — %APPDATA%\Claude\claude_desktop_config.json. Replace "cwd": "/path/to/mcp-server" with the absolute path of your checkout, then fully restart Claude Desktop. The mcp script exists in the checkout's package.json by default.

3. What to ask the agent

Open a new chat and ask Claude to run the whole scenario in one prompt:

text
Using the opensmm tools, call search_services and confirm every service
is synthetic. Then call get_quote for the first service with quantity 100
and link https://t.me/opensmm_example, call create_order with that quote
and clientReference claude-demo-1, then call create_order again with the
same quote and reference. Report both order IDs.

Expected result:

  • search_services → a catalog whose services all carry synthetic: true — the mock catalog, not real supply;
  • get_quote → osmm_quote_..., amount in USDC, quantity 100;
  • first create_order → osmm_order_..., paymentStatus: REQUIRES_PAYMENT;
  • second create_order → the same orderId, no second order created.

The replay is the main protocol check: one clientReference yields one order on any transport, stdio included.

If something looks wrong

  • A service is not marked synthetic — stop, do not order: this demo must not order real supply. Nothing is paid, so no provider executes anything.
  • The opensmm tools did not appear — check cwd (it must be the absolute path of your checkout) and fully restart Claude Desktop.
